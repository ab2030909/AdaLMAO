v0.1.1 Early Access · Go · zero dependencies

Your AdaL CLI's chaotic little bodyguard.

AdaLmao plugs into AdaL's lifecycle hooks to block destructive commands, protect your tests and secrets, watch for regressions, inject focus modes, track token usage and check Git before you push. One standalone binary. No external AI API. No database.

Download v0.1.1 → Install GitHub ↗ Commands 
# the agent tries something dumb…
bash › git reset --hard HEAD~3

>> NICE TRY!

AdaLmao blocked a dangerous operation. It was NOT executed.

Rule:   no-hard-reset
Reason: `git reset --hard` irreversibly discards uncommitted work.
Safer alternative: Use `git stash` or `git reset --soft`/`--mixed`,
                   or ask the user to run it.
Be realistic: AdaLmao is a practical guardrail layer, not a security sandbox. AdaL hooks fail open — if a hook times out or fails to launch, the action goes ahead. It's a seatbelt, not a vault. Keep backups and commit often.

# Windows PowerShell: compare with the matching line in checksums.txt
(Get-FileHash .\adalmao-windows-amd64.exe -Algorithm SHA256).Hash.ToLower()

# Linux / macOS
sha256sum -c --ignore-missing checksums.txt   # macOS: shasum -a 256 -c --ignore-missing checksums.txt

Then rename it to adalmao (adalmao.exe on Windows), put it in a permanent folder — on Windows a path without spaces, like C:\adalmao\ — and run adalmao install, then restart AdaL.

Build from source

Requires Go 1.22+ and AdaL CLI. Prefer a pre-built binary? See Download.

Windows (PowerShell)

git clone https://github.com/ab2030909/AdaLMAO.git ; cd AdaLMAO
./scripts/build.ps1
mkdir C:\adalmao ; copy dist\adalmao.exe C:\adalmao\
C:\adalmao\adalmao.exe install        # then restart AdaL
# optional: add C:\adalmao to PATH so you can type `adalmao`

Linux / macOS

git clone https://github.com/ab2030909/AdaLMAO.git && cd AdaLMAO
make build && sudo install dist/adalmao /usr/local/bin/
adalmao install                         # then restart AdaL

What install does

  • Backs up ~/.adal/settings.json first (settings.json.adalmao-<time>.bak).
  • Adds only AdaLmao-owned hooks: PreToolUse, PostToolUse, UserPromptSubmit, Stop.
  • Keeps every other setting and hook. Running it twice changes nothing.
  • Refuses to touch a settings file that isn't valid JSON.
Windows path rule (verified): AdaL runs hooks through cmd.exe /c, and a hook command containing double quotes silently failed to launch in testing. So install from a simple path like C:\adalmao\. AdaLmao converts the path to its 8.3 short form and refuses with instructions if it still has spaces. If you move the binary, run adalmao install again.

Quick start

  1. Install the hooks and restart AdaL.
    adalmao install
  2. Verify it works. The first launches each hook the way AdaL does; the second runs one real headless AdaL turn in a throwaway repo (uses a little quota).
    adalmao verify
adalmao verify --live
  3. Turn on a mode or two.
    adalmao mode on focus paranoid
  4. Dry-run the rules on any command without involving AdaL.
    adalmao check -- git reset --hard
adalmao check --delete internal/parser_test.go
  5. See everything at a glance.
    adalmao status

Verification

What was actually exercised against a real AdaL 1.11.5 on Windows 10, using throwaway repos only.

Confirmed VERIFIED

  • AdaL runs the hooks and sends session_id, cwd, hook_event_name, transcript_path, tool_name, tool_input.
  • Tools seen: bash (command), create_file, replace_by_string (file_path, old_string, new_string).
  • git reset --hard, git commit -s, rm a_test.go and editing .env were blocked before running.
  • Files and commit history intact; the agent relayed the reason.
  • Safe operations ran normally; malformed input fails open.

Not verified UNTESTED

  • Linux and macOS at runtime (cross-compiled only).
  • Every possible AdaL tool, including MCP tools (unrecognised tools aren't inspected).
  • AdaL Desktop (--ide) behaviour.
  • update --apply against a real release (none published yet).

Guardrails

Classifies file operations from what the hook can see before the tool runs.

VerdictMeaningExamples
ALLOWEDRuns normally.Creating a file, editing ordinary source.
REVIEWRuns; a note is sent to the agent.Editing a test or config file, whole-file overwrite, signature or default-value change, reading .env.
RISKYRuns; a stronger note is sent.Deleting a file, removing a public function, sudo, recursive delete.
BLOCKEDNever reaches the tool (exit code 2).Writing .env or .git/*, deleting tests, editing AdaL/AdaLmao settings, your protected paths.
AdaL says PreToolUse can't add context, so review/risky notes are queued and delivered with the next PostToolUse result in that session.

Manage protected paths

adalmao guardrails status
adalmao guardrails protect migrations/      # trailing / = whole directory
adalmao guardrails protect "secrets.*"
adalmao guardrails unprotect migrations/
adalmao guardrails disable                  # or: enable

Enforce

A deterministic rule engine for shell commands. It parses, not just greps.

RuleBlocks
no-hard-resetgit reset --hard in any form (even git -C x, sudo, bash -c "…")
protect-pathsDeleting, moving, overwriting or redirecting into .git, env files, test files, critical config, your protected paths, AdaL/AdaLmao config
no-dco-signoffgit commit -s, --signoff, -sm, --trailer Signed-off-by (unless allow_dco_signoff)
git-clean-forcegit clean -f/-fd/-fdx without a dry run
no-force-pushgit push --force / -f / +ref
no-discard-allgit checkout ., git restore ., checkout -f
git-history-rewritefilter-branch, reflog expire, gc --prune=now
catastrophic-deleterm -rf on /, ~, ., .., drive roots, home, project root
pipe-to-shellcurl … | sh, iwr … | iex
disk-destroymkfs, dd of=/dev/…, format X:, fork bombs

Not blocked, only flagged: sudo/doas, git rebase, commit --amend, branch -D, discarding single files, recursive deletes of ordinary folders. echo "git reset --hard" is not a false positive.

How commands are understood

Tokenized with quote and separator awareness (; && || |), then normalized: sudo/env wrappers, bash -c, cmd /c, powershell -Command, $(…), backticks, redirects, and git -C/-c options.

Your own rules

{
  "enforce": {
    "disabled_builtins": ["git-clean-force"],
    "rules": [
      { "id": "no-npm-publish", "enabled": true,
        "pattern": "npm publish", "action": "block",
        "reason": "Publishing requires manual review." }
    ]
  }
}

pattern matches the start of a normalized command. Add "regex": true for a regex. action is block or warn.

adalmao enforce rules                  # list built-in + custom rules
adalmao check -- npm publish          # test a rule, exit code 2 = blocked
adalmao enforce disable               # or: enable

Sentinel

After mutating tool calls it inspects git status and git diff HEAD, and reports each finding once per session.

  • Deleted test files and deleted important files
  • Fewer assertions in test diffs (removed vs added)
  • Changes to your protected paths
  • Coverage drops — only when a report exists (coverage.out, lcov.info, coverage-summary.json, coverage.xml); otherwise "unavailable"

Severity is info, warning or block. A PostToolUse hook can't undo a change, so block tells the agent to stop and report. It makes no claim of universal regression detection.

adalmao sentinel status
adalmao config set sentinel.severity block

Modes

Short instruction fragments added to every prompt via UserPromptSubmit. Up to six at once.

ModePurpose
paranoidMaximum caution; preserve your uncommitted work, prefer reversible actions.
debugFind the root cause, small targeted fixes, no unrelated refactoring.
focusStop overthinking; only the requested task.
ship-itImplementation first, minimal discussion.
perfMeasurable performance problems, readable code.
tech-cofounderProduct and architecture judgment; avoid needless features.
terseShort answers, no summaries.
teacherExplain concepts with simple examples.

Precedence on conflict: paranoid > debug > focus > ship-it > perf > tech-cofounder > terse > teacher. Known conflicts (terse/teacher, ship-it/paranoid, focus/tech-cofounder) are reported when you enable them.

adalmao modes
adalmao mode on focus debug
adalmao mode off focus
adalmao mode off                      # all off
Modes are global. AdaL only loads hooks from ~/.adal/settings.json — there's no project-level scope.

Git preflight & pre-push

Read-only. It never fetches, rebases, merges or pushes.

adalmao preflight
Branch:     feature
[✓] Working tree clean
Base:       origin/main (you are ahead 1, behind 1)
⚠️  Branch is behind origin/main.

🚨 Confirmed merge conflicts with origin/main (via git merge-tree):
- f.txt

Suggested next steps:
- Review changes before rebasing; AdaLmao never rebases for you.

Conflicts are labelled confirmed (git merge-tree --write-tree, Git ≥ 2.38) or only potential (files changed on both sides — fallback heuristic). It also reports in-progress merge/rebase, ahead/behind, and commits the base already contains.

Optional pre-push hook

adalmao prepush install
adalmao prepush status
adalmao prepush remove
  • Refuses to overwrite a pre-push hook it doesn't own (respects core.hooksPath).
  • Aborts a push only for an in-progress merge/rebase or confirmed conflicts with the base; otherwise warns.
  • Fails open if the binary moved. Bypass once with git push --no-verify or ADALMAO_SKIP_PREPUSH=1.

Budget & Guard

Real numbers from AdaL, never invented ones.

AdaL writes {"type":"usage", model, input_tokens, output_tokens, cached_read_input_tokens, cache_creation_tokens, reasoning_tokens} records into the transcript it passes to hooks. adalmao budget sums them per model (subagents included). Until usage exists it prints Usage data unavailable.

AdaL reports no prices, so cost is an estimate from prices you provide. With no prices set, there is no cost and Guard stays silent.

adalmao budget
adalmao guard status
adalmao config set budget.input_price_per_mtok 3
adalmao config set budget.output_price_per_mtok 15
adalmao config set budget.cached_input_price_per_mtok 0.3
adalmao config set budget.session_limit 5
adalmao config set budget.warning_threshold 0.8

Guard warns once at the threshold and once at the limit through prompt context. It cannot stop spending — AdaL gives hooks no way to.

Loop

A bounded experiment: ask AdaL to do a task, run your verification command, record the result, repeat until it passes or limits hit.

adalmao loop --task "Make the failing test pass" \
             --verify "go test ./..." \
             --max-iterations 3 --max-minutes 30 --yes
  • Explicit start: without --yes it only prints the plan.
  • Isolated: works in a new git worktree and branch from HEAD; your working tree is untouched. Never merges.
  • Safe default: --permission-mode acceptEdits (edits run, shell commands don't). Your verify command is refused if enforce rules would block it.
  • Capped: hard maximums 10 iterations and 240 minutes. Score is pass/fail by exit code. Ledger at ~/.adalmao/loops/*.jsonl.
  • No token budget — AdaL exposes none to wrappers. Your installed hooks still guard the loop's agent.

Tune, Party, Spank, Attest

Tune read-only

Shows your real model, effort setting and supported levels from AdaL's files. Never edits them. Change via /model config or adal --thinking-effort.

Party manual

Named mode presets: builder, reviewer, optimizer, mentor. adalmao party use reviewer. No per-subagent assignment (AdaL has none).

Spank guidance

adalmao spank explain — how to keep long jobs alive (tmux, caffeinate, power settings). Changes nothing.

Attest opt-in

Optional Assisted-by: AdaL trailer hook. Never signs or adds Signed-off-by. Needs attest.enabled=true.

adalmao tune
adalmao party profiles | show reviewer | use reviewer
adalmao attest [install-hook | remove-hook]

Configuration

~/.adalmao/config.json — override the folder with ADALMAO_HOME (and AdaL's with ADAL_HOME). Missing file = defaults; invalid = defaults plus a warning; unknown fields are preserved when saving.

{
  "version": 1,
  "general":    { "enabled": true, "active_modes": ["focus"] },
  "guardrails": { "enabled": true, "protect_env_files": true, "protect_git_directory": true,
                  "protect_tests": true, "protect_config_files": true,
                  "warn_on_public_api_changes": true, "warn_on_default_value_changes": true,
                  "protected_paths": ["migrations/", "secrets.yml"] },
  "enforce":    { "enabled": true, "allow_dco_signoff": false, "disabled_builtins": [], "rules": [] },
  "sentinel":   { "enabled": true, "severity": "warning" },
  "budget":     { "enabled": true, "session_limit": 5.0, "warning_threshold": 0.8,
                  "input_price_per_mtok": 0, "output_price_per_mtok": 0, "cached_input_price_per_mtok": 0 },
  "git":        { "preflight_enabled": true, "base_branch": "" },
  "attest":     { "enabled": false, "trailer": "Assisted-by: AdaL" },
  "profiles":   { "builder": ["ship-it"], "reviewer": ["paranoid"], "optimizer": ["perf"], "mentor": ["teacher"] }
}

Edit safely with adalmao config set budget.session_limit 3 (validated before saving). Logs live in ~/.adalmao/decisions.log (likely secrets redacted). For debugging, ADALMAO_CAPTURE=1 records raw hook payloads to capture.jsonl — opt-in, may contain code and prompts.

Update & uninstall

adalmao update              # compare installed vs latest release
adalmao update --apply      # download, verify SHA-256, swap binary (old kept as .old)
adalmao uninstall           # removes only AdaLmao's hooks; your data stays
adalmao uninstall --purge   # also deletes ~/.adalmao

The updater downloads only from HTTPS GitHub hosts, requires a matching checksums.txt, and never runs downloaded scripts. v0.1.1 is the first published release, so there is nothing newer to fetch yet and update --apply has not been exercised against a real release. Uninstall never restores an old backup over newer settings.

Limitations & security

  • Fail-open hooks: timeout, crash or launch failure lets the action through.
  • Hooks can allow, block (PreToolUse, UserPromptSubmit) or add context (PostToolUse, UserPromptSubmit); they can't modify tool input, and PostToolUse can't undo a change.
  • AdaL loads hooks only from ~/.adal/settings.json and must be restarted after install.
  • AdaL publishes no tool list. Detection is by name keywords plus common fields; unrecognised tools (MCP included) aren't inspected.
  • Shell parsing is a practical approximation: eval, encoded payloads, scripts that delete things internally, and anything run outside AdaL aren't covered.
  • No native status line, no per-subagent hooks, no token-budget API. AdaL may auto-update itself when invoked.

Troubleshooting

Nothing gets blocked

Restart AdaL after adalmao install. Run adalmao verify; if the launch test fails, your install path probably needs quoting — move the binary to C:\adalmao\ and re-install. Then adalmao verify --live proves AdaL itself calls the hook.

"hook did not launch"

The binary moved or was deleted. Re-run adalmao install from its current location.

Something was blocked that shouldn't be

Find the rule with adalmao log or adalmao check -- <command>. Disable a built-in with disabled_builtins, remove a protected path with guardrails unprotect, or allow sign-offs with enforce.allow_dco_signoff.

Budget says "Usage data unavailable"

Usage is recorded once you submit prompts with the hooks installed. Cost also needs your own prices (see Budget).

Config looks wrong

adalmao config validate, adalmao config show, adalmao config path.

Report a bug

Open an issue at github.com/ab2030909/AdaLMAO/issues with:

  • Your OS and adalmao version, plus your AdaL version
  • The output of adalmao verify
  • What you expected vs. what happened

Linux and macOS runtime reports are especially welcome — that's the main gap in this release. Don't paste secrets; ~/.adalmao/decisions.log redacts likely secrets, but check before sharing. For security-sensitive issues, contact the maintainer privately instead of filing a public issue. Contributions: see CONTRIBUTING.md.
